# Feature Specification: Agent 检测规则引擎

**Feature Branch**: `004-detection-rules`
**Created**: 2026-05-14
**Status**: Draft
**Input**: 用户描述：为 AI 调度平台开发检测规则引擎，内置 11 种检测策略，支持 Web 端配置，
与 Agent 前后置检测挂载交互。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 管理员在 Web 端配置 Agent 检测策略 (Priority: P1)

平台管理员需要为特定 Agent 开启/关闭各项检测策略，并为每条策略配置具体参数（如限流阈值、
违规关键词、处置动作）。不同 Agent 的同一策略可以有各自独立的配置；未单独配置时自动使用
全局默认值。

**Why this priority**: 这是整个检测规则体系的入口，没有 Web 端配置能力，后续所有策略均无法
落地使用，是阻塞性前提。

**Independent Test**: 进入某 Agent 的策略配置页，启用"限流防刷"策略并设置参数后保存，
再进入另一 Agent 相同策略页，验证两者配置互相独立、均可保存成功并即时生效。

**Acceptance Scenarios**:

1. **Given** 管理员进入某 Agent 的"检测规则"配置页，
   **When** 从策略列表中找到"限流防刷"并点击"启用"并填写每分钟请求上限，
   **Then** 保存后该配置仅对此 Agent 生效，其他 Agent 的限流阈值不受影响。

2. **Given** 管理员未对某 Agent 的某策略做单独配置，
   **When** 查看该策略配置详情，
   **Then** 显示系统全局默认值，且有明确标注"当前使用默认配置"。

3. **Given** 管理员已对某策略配置了处置动作为"拦截"，
   **When** 将处置动作改为"记录（仅记录）"并保存，
   **Then** 变更立即生效，后续请求按新的处置动作执行，且审计日志记录此配置变更。

4. **Given** 管理员进入"违规内容拦截"策略配置，
   **When** 分别为政治违禁、色情低俗、暴力违法、攻击类四个子类型独立开关，
   **Then** 每个子类型可独立启用/禁用，互不影响。

---

### User Story 2 — 前置策略自动拦截/处置不合规请求 (Priority: P1)

当 API 调用方发起 Agent 调用时，系统自动依次执行该 Agent 绑定的所有前置策略。任何一条策略
命中后，按配置的处置动作执行（如拦截则立即返回错误，改写则修改请求后继续）。管理员和运营人员
可以实时感知到哪些请求被策略拦截。

**Why this priority**: 前置保护是平台安全的第一道门，与 US1 同为核心交付。

**Independent Test**: 在测试 Agent 上启用"限流防刷"策略并设置极低阈值（如每分钟 1 次），
连续调用 2 次，验证第 2 次被拦截并返回明确的错误提示，审计日志中有对应的命中记录。

**Acceptance Scenarios**:

1. **Given** Agent 绑定了"身份校验"策略（处置：拦截），
   **When** 调用方使用无效/过期 Token 发起请求，
   **Then** 系统在 Agent 执行前拦截请求，返回"身份校验失败"错误，Agent 不被触发。

2. **Given** Agent 绑定了"隐私信息前置脱敏"策略（处置：改写），
   **When** 请求内容包含手机号或身份证号，
   **Then** 系统将 PII 信息脱敏后，把修改后的请求传递给 Agent，原始明文不流转至 Agent。

3. **Given** Agent 绑定了多条前置策略，
   **When** 第一条策略（身份校验）触发"拦截"处置，
   **Then** 后续策略不再执行，直接返回拦截结果（短路机制）。

4. **Given** Agent 绑定了"意图&业务范围合规"策略（处置：记录 Review），
   **When** 请求意图偏离 Agent 的声明业务范围，
   **Then** 请求仍继续流转至 Agent，但系统标记此请求为"待人工复核"，写入 Review 队列。

5. **Given** Agent 绑定了"RBAC 权限前置校验"策略（处置：降级），
   **When** 调用方角色权限不足以使用完整功能，
   **Then** 请求以受限模式继续执行（如只读操作），用户收到功能受限提示。

### User Story 3 — 后置策略校验 Agent 响应 (Priority: P2)

Agent 生成响应后，系统自动执行该 Agent 绑定的后置策略，检测响应是否包含隐私泄露、违规
内容或不符合业务规则的内容。命中后按配置处置（如替换响应或送人工审批后再返回）。

**Why this priority**: 后置保护防止 Agent 无意中泄露敏感数据或产生不合规输出，是合规交付
的关键，优先级略低于前置（前置问题更直接影响安全）。

**Independent Test**: 在测试 Agent 上启用"后置隐私防泄密"策略，构造一条会使 Agent 回复
含手机号的提示词，验证最终返回给调用方的响应中手机号已脱敏。

**Acceptance Scenarios**:

1. **Given** Agent 绑定了"后置隐私防泄密"策略（处置：改写），
   **When** Agent 响应中包含用户手机号或数据库内部字段，
   **Then** 系统将敏感信息脱敏后再返回给调用方，脱敏详情写入审计日志。

2. **Given** Agent 绑定了"业务结果后置规则校验"策略（处置：重试），
   **When** Agent 响应格式不符合预定义的业务规则（如缺少必填字段），
   **Then** 系统自动触发 Agent 重试，超过最大重试次数后降级返回兜底响应。

3. **Given** Agent 绑定了"人机审批"策略，
   **When** Agent 生成响应后，
   **Then** 响应进入审批队列，调用方收到"等待审批"状态，
   审批通过后结果才返回给调用方。审批通知通过站内消息推送给平台内"审批员"角色用户，
   审批员在 Web 端审批队列中处理待审批条目。

### User Story 4 — 审计员查看策略命中与处置记录 (Priority: P2)

运营或安全审计人员需要查看所有策略的执行记录：哪些请求命中了哪条策略、采用了什么处置动作、
最终结果如何。支持按 Agent、策略类型、处置动作、时间段等维度筛选。

**Why this priority**: 审计可见性是合规要求，支持事后复盘和安全运营，优先于个别策略优化。

**Independent Test**: 触发若干次策略拦截后，进入审计日志页，验证每条命中记录包含 Agent 名称、
策略名称、处置结果、触发时间，且支持按策略类型过滤。

**Acceptance Scenarios**:

1. **Given** 某请求被"违规内容拦截"策略拦截，
   **When** 审计员在日志页搜索该时段记录，
   **Then** 能查到该记录，包含：触发时间、Agent 名称、策略名称、命中详情摘要、处置动作。

2. **Given** 存在多类策略的命中记录，
   **When** 审计员按"策略类型 = Prompt 注入防护"筛选，
   **Then** 只展示该策略类型的记录，其他策略记录不显示。

3. **Given** 某请求被标记为"待人工复核（Record Review）"，
   **When** 审计员进入 Review 队列，
   **Then** 能看到该请求的原始内容、Agent 响应、标记原因，并可标注"已复核/升级处理"。

---

### User Story 5 — 管理员设置全局默认策略配置 (Priority: P3)

平台管理员可以为每种检测策略设置全局默认参数，新建 Agent 或未单独配置的 Agent 自动继承
全局默认配置，减少重复配置工作量。

**Why this priority**: 提升运营效率，但不影响核心安全功能交付。

**Independent Test**: 在全局配置中将"限流防刷"默认阈值设为 100 次/分钟，新建一个 Agent
且不单独配置该策略，验证该 Agent 的限流策略生效且阈值为 100 次/分钟。

**Acceptance Scenarios**:

1. **Given** 管理员在全局设置中修改"违规内容拦截"默认处置为"记录（仅记录）"，
   **When** 某 Agent 未对该策略做单独配置，
   **Then** 该 Agent 的违规内容拦截策略自动使用新的全局默认处置动作。

2. **Given** 某 Agent 已做单独配置覆盖了全局默认，
   **When** 管理员修改该策略的全局默认值，
   **Then** 已有 Agent 的单独配置不受影响（per-Agent 配置优先）。

---

### Edge Cases

- 多条前置策略同时命中同一请求时，短路规则（首个"拦截"立即终止）能否正确工作？
- 策略参数配置为空/无效值时，系统如何提示并阻止保存？
- Agent 正在被调用时，管理员同时修改其策略配置，热加载是否会导致竞态？
- 后置人机审批策略审批超时（如审批者长时间不响应）时，如何保证调用方不永久阻塞？
- 检测策略服务自身故障时，是放行请求还是拦截请求（需可配置的 fail-open/fail-close 模式）？

## Requirements *(mandatory)*

### Functional Requirements

**策略管理**

- **FR-001**: 系统 MUST 内置 11 种检测策略，分为 8 种前置策略（P-01～P-08）和 3 种后置策略（A-01～A-03）
- **FR-002**: 每种策略 MUST 支持全局默认配置和 per-Agent 独立覆盖配置两级，per-Agent 优先
- **FR-003**: Web 端 MUST 提供每种策略的参数配置界面，展示各配置项的说明和默认值
- **FR-004**: 每条策略 MUST 可独立启用/禁用，互不影响
- **FR-005**: 违规内容拦截策略（P-03）MUST 支持政治违禁、色情低俗、暴力违法、攻击类四个子类型独立开关

**处置动作**

- **FR-006**: 每条策略 MUST 支持配置以下处置动作之一或组合：拦截、改写、记录 Review、重试、
  记录（仅记录）、降级、转人工、告警
- **FR-007**: 前置策略触发"拦截"时，MUST 立即短路，后续前置策略和 Agent 不再执行
- **FR-008**: "重试"处置 MUST 支持配置最大重试次数，超限后执行兜底处置动作
- **FR-009**: 策略检测超时 MUST 有可配置的降级行为（fail-open 放行 + 告警，或 fail-close 拦截）

**执行与集成**

- **FR-010**: 前置策略 MUST 按固定顺序（P-01 → P-08）依次执行
- **FR-011**: 后置策略 MUST 按固定顺序（A-01 → A-03）依次执行
- **FR-012**: 策略配置变更 MUST 热加载生效，无需重启服务

**审计与可观测性**

- **FR-013**: 所有策略命中事件 MUST 写入审计日志，包含：策略编号、Agent ID、用户ID、命中摘要、
  处置动作、时间戳
- **FR-014**: Web 端 MUST 提供审计日志查询页，支持按 Agent、策略类型、处置动作、时间段筛选
- **FR-015**: 被标记为"记录 Review"的请求 MUST 进入可查看的 Review 队列，支持人工标注处置状态
- **FR-016**: 策略配置的每次变更 MUST 记录操作审计（变更人、变更前后值、时间）

### Key Entities

- **DetectionPolicy（检测策略模板）**: 策略编号、策略名称、所属阶段（前置/后置）、描述、
  全局默认配置（JSON）
- **AgentPolicyBinding（Agent 策略绑定）**: Agent ID、策略编号、是否启用、per-Agent 配置（JSON）、
  处置动作配置、更新时间
- **DetectionEvent（检测事件）**: 事件 ID、Agent ID、策略编号、触发时间、命中详情、处置动作、
  处置结果、关联请求 ID
- **ReviewQueue（人工复核队列）**: 事件 ID、原始请求摘要、Agent 响应摘要、标记原因、复核状态、
  复核人、复核时间
- **PolicyConfigAudit（配置变更审计）**: 操作人、Agent ID（null 为全局）、策略编号、变更前值、
  变更后值、操作时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员可在 5 分钟内完成单个 Agent 全部策略的启用与参数配置，无需培训文档辅助
- **SC-002**: 前置策略从请求进入到处置完成（拦截/改写/放行）的平均耗时 MUST 不超过 200ms（不含
  Agent 本身执行时间）
- **SC-003**: 策略配置变更热加载生效时间 MUST 不超过 5 秒
- **SC-004**: 审计日志查询 1 万条以内记录的响应时间 MUST 不超过 3 秒
- **SC-005**: 所有策略命中事件的审计记录完整率 MUST 达到 100%（不允许漏记）
- **SC-006**: 对于"违规内容拦截"和"Prompt 注入防护"两类高风险策略，误拦截率（合规请求被错误拦截）
  MUST 低于 1%
- **SC-007**: 系统支持单 Agent 每秒至少 100 次并发请求时，策略执行不产生明显排队延迟

---

## Assumptions

- 本次实现范围为"检测规则引擎"本身（策略定义、绑定、执行、审计），不包括检测算法的训练/优化
- 违规内容检测（P-03）的底层能力依赖已有的内容审核服务或 LLM 分类能力，规则引擎层不实现算法
- 隐私脱敏（P-05、A-01）的实体识别依赖现有的 NER 能力或正则规则，规则引擎层负责调用和结果处置
- Agent 调度平台已有用户身份（Token/Session）管理机制，身份校验策略复用已有鉴权体系
- 人机审批（A-03）的审批通知方式默认为站内消息，外部渠道（钉钉/邮件）视为扩展需求
- 业务前置硬性规则（P-08）仅支持内置规则类型的组合配置，包括：时段限制、地域限制、
  IP 黑名单、用户黑名单四类；管理员通过 Web 端表单选择并填写规则参数，无需自定义表达式
- 本次 Web 端检测规则配置页嵌入到现有 Agent 管理页面内（Agent 详情页新增"检测规则"Tab），
  不作为独立一级菜单
- 检测策略的执行超时默认配置为：超时则放行（fail-open）并触发告警，此默认值可在 Web 端修改
